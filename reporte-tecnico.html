1. Resumen y arquitectura

Se implementó una API REST de productos con Java 17 y Spring Boot 3.5.7. Incluye validación Jakarta, acceso MongoDB mediante Spring Data, control de duplicados, formato JSON uniforme para errores, pruebas unitarias y pruebas MVC.

Componentes: ProductoController recibe HTTP y valida; ProductoService aplica reglas de negocio y traduce conflictos concurrentes; ProductoRepository accede a MongoDB; Producto se almacena en la colección productos; GlobalExceptionHandler normaliza errores.

Stack: Java 17.0.11, Maven Wrapper 3.10.0, Spring Boot 3.5.7, Spring MVC, Spring Data MongoDB, Jakarta Validation, JUnit 5, Mockito, AssertJ, MockMvc, Testcontainers y JaCoCo 0.8.13.

2. API REST

Método y rutaResultado
GET /api/productos200 · colección
GET /api/productos/{id}200 o 404
POST /api/productos201 + Location; 400 o 409
PUT /api/productos/{id}200; 400, 404 o 409
DELETE /api/productos/{id}204 o 404

El cuerpo requiere nombre/código no vacíos, precio positivo y stock no negativo. El código tiene índice único. Los errores exponen timestamp, status, error, message, path y detalles de validación; nunca trazas ni información interna de MongoDB.

{"nombre":"Teclado","codigo":"TEC-001","precio":899.0,"stock":5}

4. Persistencia y ambiente

La URI se configura mediante MONGODB_URI. Docker Compose define MongoDB 7.0.14 con volumen persistente y credenciales por archivo local excluido de Git.

La prueba real con mongosh contra localhost:27017 devolvió ECONNREFUSED. Docker no está instalado y no se encontró servidor/servicio local. No se afirma una operación real de lectura/escritura.

5. Calidad, evidencias y bloqueos

La verificación JaCoCo aprobó los umbrales configurados. SonarQube no pudo analizarse: localhost:9000 no respondió y no había SONAR_TOKEN.

Quality Gate: SIN RESULTADO. No se declara PASSED ni FAILED.

El scanner Maven y la ruta del XML JaCoCo están configurados. Para completar el análisis, iniciar SonarQube autorizado, establecer el token como variable de entorno y ejecutar:

.\mvnw.cmd clean verify sonar:sonar "-Dsonar.host.url=http://localhost:9000"

La carpeta evidencias/ contiene el log Maven, el CSV JaCoCo y los resultados de tests. No se fabricaron capturas HTTP: las capturas Postman/cURL contra MongoDB real requieren iniciar el servicio. Los casos 400/404/409 sí tienen pruebas MockMvc.

6. Conclusión

El CRUD, sus validaciones y contrato JSON de errores quedaron implementados. Las suites unitarias y MVC aprobaron, con 92.55% de líneas y 100% de ramas. La integración real MongoDB, las capturas HTTP de extremo a extremo y el Quality Gate quedan pendientes de infraestructura disponible; las limitaciones se reportan explícitamente.
